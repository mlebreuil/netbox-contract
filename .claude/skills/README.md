# .claude/skills

Project-local Claude Code skills. Each skill is a directory with a `SKILL.md` (the entry point); supporting files live
next to it. The rules that apply to all of them are in [`AGENTS.md`](../../AGENTS.md) and the
[constitution](../../.specify/memory/constitution.md).

## Three kinds of skills

| Skills | Purpose | Maintained by |
|---|---|---|
| `speckit-*` | The Spec Kit workflow: assess, specify, clarify, plan, tasks, analyze, implement | Generated by Spec Kit (see `.specify/integrations/`); do not edit by hand |
| `netbox-plugin-development` | Reference: how NetBox plugins are built (models, views, API, GraphQL, forms, tables, testing, packaging, the 4.7 changes) | Vendored from NetBox Labs; refreshed by copying, never edited except its "In netbox-contract" note |
| the others (below) | Mechanical checklists for recurring changes to this plugin | Hand-written, edited like code |

The checklists answer *"which files does this change touch?"*. They do not replace the Spec Kit sequence: a feature is
specified and planned first, then `/speckit-implement` follows the matching checklist. For the NetBox API behind a
step (a base class, a mixin, a registration), the checklists point to the `netbox-plugin-development` references
instead of repeating them.

| Skill | Use it to |
|---|---|
| `netbox-plugin-development` | Look up the NetBox plugin API (base classes, views, serializers, GraphQL extensions, test classes, packaging) |
| `add-model` | Add a model with the full NetBox stack |
| `add-model-field` | Add a field to an existing model |
| `remove-model` | Deprecate, then remove, a model |
| `remove-model-field` | Deprecate, then remove, a model field |
| `add-plugin-setting` | Add a plugin setting (`default_settings`) |
| `remove-plugin-setting` | Deprecate, then remove, a plugin setting |
| `run-tests` | Run lint, the test suite, the migration check and the identifier check |
| `draft-changelog` | Write the `CHANGELOG.md` entries of a release, by kind of change |
| `release-plugin` | Prepare and publish a plugin release |

## Not used in this repository

`speckit-taskstoissues` is generated by Spec Kit and kept as is, but do not run it unless the maintainer asks for it:
it creates issues with the GitHub MCP server, titled `T001: ...` without the feature number (the project writes
`NNN-T001`), outside the issue forms and without labels, and agents do not open issues on their own (`AGENTS.md`, AI
policy).

## Conventions

- Names are `lowercase-kebab-case`; the directory name equals the `name` in the frontmatter.
- A skill says *why* it makes a choice, not only what to do: the reason is more durable than the instruction.
- A skill that publishes or deletes something (release, removal) states what it confirms with the maintainer first.
- Skill files are exempt from the identifier check (`utils/spec_ids.py`), so they may use placeholders such as
  `NNN-FR-001`.

## Origin

- `add-model`, `add-model-field`, `remove-model`, `remove-model-field`, `add-plugin-setting`, `remove-plugin-setting`,
  `run-tests`, `draft-changelog` and `release-plugin` are adapted from the skills of the
  [NetBox](https://github.com/netbox-community/netbox/tree/main/.claude/skills) repository (Apache-2.0), rewritten for
  a plugin: NetBox's skills target core's layout and its release process.
- `netbox-plugin-development` is copied from [netboxlabs/skills](https://github.com/netboxlabs/skills) (Apache-2.0;
  the license text is in its directory). The commit it was taken from is in the note at the top of its `SKILL.md`.

Not taken from `netboxlabs/skills`, on purpose: the skills for operating NetBox itself (administration, API
integration, scripts, config templates, branching, Diode, migration and the review skills) and the `build-plugin`
command, which scaffolds a new plugin. This plugin already exists and has its own checklists.

## Refreshing `netbox-plugin-development`

When NetBox ships a release, or every few months:

1. `git clone --depth 1 https://github.com/netboxlabs/skills` and diff `skills/netbox-plugin-development/` against
   this directory.
2. Copy the new files over, then restore the "Vendored from..." and "In netbox-contract" note at the top of
   `SKILL.md` and update the commit hash and date in it.
3. Read the diff against the checklists above: a new NetBox API or a removal (see its `netbox-4.7-migration.md`
   reference) may change a step. Where upstream and this repository differ, the note lists the difference; the
   constitution wins.
