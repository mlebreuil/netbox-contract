# Documentation screenshots

Regenerates the screenshots in `docs/img/` from a real NetBox running the plugin, with the same demo data every
time. Run it before a release, after any change to a page that the docs show:

```bash
utils/docs_screenshots/make_screenshots.sh                 # all screenshots
utils/docs_screenshots/make_screenshots.sh invoice contract  # only some of them
```

Then review the images (`git diff --stat docs/img`, and look at them) and commit the ones that changed.

## What it does

1. Installs Playwright and headless Chromium in `utils/docs_screenshots/.venv` (first run only; git-ignored).
2. Drops and recreates the database `netbox_docs`, then migrates it. Your development database is never used: the
   script refuses to run if the two names are the same.
3. Seeds the demo data with `seed.py`: the "Paris DC1 colocation" contract from Acme Colocation, with one line of each
   billing method, a non-billable child contract, three assigned objects and three quarterly invoices whose lines are
   generated by the plugin.
4. Runs NetBox with `docs_configuration.py` on port 8001. That configuration is your development configuration
   (`netbox/configuration.py` of the NetBox checkout) with the `netbox_docs` database, Redis databases 4 and 5,
   `DEBUG` off and only this plugin enabled.
5. Logs in as `admin` / `admin` (created in `netbox_docs` only) and captures each screenshot with `capture.py`, in
   dark mode at 1440 px wide, into `docs/img/`.

A full run takes about four minutes, most of it for the migrations.

## Requirements

- The development layout: the NetBox checkout next to this repository (`../netbox`) with its virtualenv in `venv/`,
  the plugin installed in it, and PostgreSQL and Redis reachable as configured there.
- The PostgreSQL user of the NetBox configuration must be allowed to create databases.
- If Chromium does not start because system libraries are missing, install them once with
  `sudo utils/docs_screenshots/.venv/bin/playwright install-deps chromium`.

Environment variables: `NETBOX_DIR` (NetBox checkout), `NETBOX_PYTHON` (its Python), `DOCS_DB_NAME`
(default `netbox_docs`), `DOCS_PORT` (default `8001`), `DOCS_OUT` (default `docs/img`), `DOCS_REDIS_TASKS_DB` and
`DOCS_REDIS_CACHING_DB` (default 4 and 5).

## Adding or changing a screenshot

Screenshots are listed in `SHOTS` in `capture.py`. Each one is a page and two elements: the crop goes from the top
of the first element to the bottom of the last one, across the content area, so it follows layout changes.
Selectors are Playwright selectors; the helpers cover the usual cases:

- `HEADER`: the page title, buttons and tabs.
- `FIRST_ROW`: the first row of panels of a detail page.
- `FIRST_ALERT`: the first message of a page (for example the lock notice of a contract).
- `panel('Invoices')`: the panel whose title starts with "Invoices".
- `LIST_TABLE`: the table of a list page.

Pages use the primary keys that `seed.py` writes (`{contract}`, `{contract_line}`, `{usage_line}`, `{invoice}`,
`{invoice_line}`); add a key there when a new screenshot needs another object. Then reference the image from the
docs as `![Title](img/<name>.png "title")`.

When a page needs data the seed does not have (a new field, a new model), extend `seed.py` so that the screenshot
shows the feature with realistic values.
